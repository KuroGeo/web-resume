# 私有简历内容源与公开网页、PDF 发布设计

状态：方案已获同意；本书面设计待确认，尚未实现。

## 目标与已核实的现状

只维护一份简历内容库，生成网站、公开中英文 PDF 和私人投递版本。继续保留公开网站源码；私人资料、私人版本及其构建中间文件不得进入公开仓库或网站。

2026-09-23 已通过认证 GitHub API 确认 `KuroGeo/resume` 是 private，`KuroGeo/web-resume` 是 public。网站工作树干净，HEAD 与 origin/main 一致。网站为纯静态站，Pages 工作流直接上传 public/。resume.html 使用 resume-document.js 中另一份正文，通过 window.print() 保存 PDF。其他网页内容分布在 resume-content.js、profile-data.js 及 HTML 中。

私有项目已有 RenderCV/Typst、中文和英文 YAML、其他私人版本与生成脚本。复用现有排版工具，不另建 PDF 渲染系统。旧脚本的输入文件约定不一致，不能直接作为新发布入口。

## 内容归属与迁移

私有 resume 仓库拥有唯一人工维护的内容库和版本配置。采用稳定条目 ID；基础资料、经历、项目分别组织，中英文为同一条目的两个语言字段。网站长文和 PDF 摘要可以不同，均归同一条目管理，不要求 PDF 塞入网页全部内容。

公开配置逐项列出允许输出的字段、条目和语言；默认拒绝未列出的内容，避免递归复制整个对象。私人版本配置只保存选材、排序和必要的措辞覆盖。版本配置不能通过覆盖操作绕过公开字段筛选。

首次迁移仅将网站已存在的内容作为公开基线。私人资料不因合并而获得公开资格；公开与私人源中的事实有冲突时保留公开基线，报告差异供用户决定，不自动替换。既有私人版本完整保留，迁移后对照原 PDF 验证，确认等价前不删除旧输入。

将当前各网页中重复维护的简历事实、项目说明迁入上述内容库。网站专属交互文案、布局、图片和模板留在 web-resume。公开生成文件标明生成来源，不再手改内容。

## 生成和发布边界

在本地私有工作目录或私有仓库的 Actions 中执行：

1. 校验内容与版本配置，投影出仅含白名单字段的公开数据。
2. 用同一份投影生成网页数据及 RenderCV 公开输入，渲染中文和英文 PDF。
3. 在全新临时目录中组装公开发布包，固定包含 public/generated/resume.json、public/downloads/resume-zh.pdf、public/downloads/resume-en.pdf。公开 JSON 包括网页需要的公开长文、摘要和项目数据。
4. 校验全部文件后，一次性更新 web-resume 的固定产物路径；禁止同步整个私有目录、rendercv_output/ 或通配复制所有 PDF。
5. 网站只读取这份公开 JSON。resume.html 保留可阅读的 HTML 正文和教育锚点，新增按当前语言下载 PDF 的链接；打印机动画保留，完成后进入公开简历页。

公开发布包不包含私人版本名称、私人源路径、完整 YAML、Typst 中间文件、调试数据、私有提交记录或凭证。PDF 元数据和文本也在验证范围内。路径限制同时拒绝符号链接、路径穿越及额外文件。

私有 PDF 使用独立命令与独立输出目录，只生成到本地或私有存储，绝不共用公开发布暂存目录。浏览器和公开 Actions 不拉取私人源文件。

## 自动更新与凭证

私有仓库增加专用工作流，仅从受信任的 main 分支 push 或手动触发生成。源内容无公开变化时不写公开仓库；有变化时仅提交三个固定产物文件，以一个提交更新，随后触发现有 Pages 流程。

跨仓库发布使用仅作用于 web-resume 的专用写入凭证，保存在私有仓库的 Actions secret 中；不将本机 gh 登录凭证复制到 CI。配置发布凭证作为交付事项单独核验。凭证缺失时构建与本地验证仍可完成，但必须明确报告自动发布尚未启用。

公开仓库的 Pages 流程保持只读私有数据的能力为零。发布需确保所用凭证确实触发目标仓库 push 工作流，并以实际运行结果验证，不能以 push 成功代替部署成功。

## 失败与回退

缺字段、缺语言、非法路径、PDF 渲染失败、隐私检查失败，均在公开写入前中止。生成失败不发布半套产物。工作流串行发布，更新前刷新目标分支；并发冲突中止或基于最新分支重试，不强推。

首次上线前下载链接与两份 PDF 一起交付，避免坏链接。回退使用公开仓库的前一套产物。已公开内容的历史副本无法靠删除当前文件撤回，因此隐私检查必须在首次公开之前完成。

## 验证与完成标准

- 使用合成私人字段和私人条目作为泄露哨兵：新增字段、嵌套字段、私人覆盖均不得出现在公开 JSON、网页输出或 PDF 文本/元数据中。测试不把真实私人内容复制到公开测试用例。
- 发布包白名单、路径穿越、额外文件和软链接均有拒绝测试；构建失败后确认目标仓库没有更新。
- 同一条公开经历修改后，网页与对应语言 PDF 同步更新；私人版本选择、排序和覆盖功能有效。
- 实际渲染两份 PDF，检查中文字体、分页、文本可提取性、链接及无裁切；与网站公开基线核对内容。
- 保留并运行现有 node tests/validate-site.mjs，根据新数据加载方式调整有意义的断言；浏览器验证中英文、项目详情、教育锚点、打印机交互与 PDF 下载。
- 最终分别报告本地验证、两个仓库的提交/推送状态、CI、Pages 部署和线上 PDF 下载结果。未配置凭证或未完成线上验证时不宣称端到端自动化已完成。

## 范围

不改变网站视觉方向，不公开更多私人信息，不增加后台登录、在线简历编辑器或第三方简历服务。两个仓库仍保留，但内容只在私有仓库维护。
